# Context Engine

Fundação interna determinística. Entrada pública do backend: AuthorizationGateway.prepareContext(context, request). companyId, userId e sessionId vêm do contexto autenticado do backend, nunca do input da IA. Reutiliza validação de sessão/vínculo/tenant ativos, RBAC, validação de input, autorização de domínio e Human Approval. Não executa a ação da capability. Ausência de política context nega acesso. Aprovações exigidas neste método são de finalidade CONTEXT_PREPARATION. O Provider Gateway usa prepareGenerationContext, que exige finalidade GENERATION. Ambos rejeitam aprovações EXECUTION; preparar contexto não autoriza execução posterior da ação.

Capabilities registram uma política imutável com maxBytes e até 16 campos ordenados por relevância. Cada campo precisa de authorize explícito e read, implementados pelo backend. Autorizações recebem o input específico da requisição; false omite o campo sem leitura, erro interrompe a preparação. Readers devem consultar apenas projeções mínimas, limitar resultados na origem e sempre filtrar por companyId e permissões de domínio. Cada resultado declara companyId e divergências descartam toda a resposta. Essa declaração é uma defesa adicional, não substitui o filtro da consulta. Não há readers de domínio, histórico automático, cache compartilhado, acesso Prisma pelo engine ou acesso direto da IA ao banco.

content contém somente JSON dos campos autorizados, sem serialização automática de inputs, registros ou histórico. Dados são conteúdo não confiável, nunca instruções ou autoridade. O limite explícito por capability não pode superar 16384 bytes UTF-8; maxBytes por request só reduz o teto. O limite inclui o JSON de content, não os metadados de transporte companyId/capability/correlationId. Resumo opcional é fornecido pelo reader autorizado e deve respeitar a mesma projeção/permissões. Se necessário, usa resumo, depois truncamento de prefixo, identificados por representation e reduced. Não há sumarização por modelo.

Observabilidade registra context.prepare, tenant, capability, correlação, resultado e latência antes de devolver conteúdo; falha de audit impede entrega. Nenhum texto, resumo ou input é enviado ao audit. Contexto é reconstruído e reautorizado por request.

Não há chamada de IA ou consumo efetivo a liquidar nesta etapa. sizeBytes mede bytes, não tokens e não deve ser usado como maxInputTokens do AI Metering. A futura integração deve contar o prompt completo com o tokenizer apropriado, reservar orçamento no AI Metering antes do provider e liquidar uso real depois; preparar contexto não libera budget nem execução de IA. Provider, Model Router, RAG e integração de execução real permanecem fora do escopo.
